# Bed-Type Filter ("Two separate beds") Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a header filter tag — "Two separate beds" — that matches every property having two beds of the *same* type in any one room, and build it on a universal (count + bed-type) mechanism so future tags like "3 × King size" are trivial to add.

**Architecture:** Reuse the existing 5-layer filter pipeline exactly as `AmenityFilter` does: (1) a tag source-of-truth file that builds URL params + a client-side gate, (2) React context state, (3) a header pill component, (4) an API-route merge, (5) a Mongo query builder. The only new mechanism is a MongoDB `$expr` predicate (count of a bed type within each `rooms_info[].beds` sub-array), because beds live in a nested array and can't be matched with the existing flat whitelist operators.

**Tech Stack:** Next.js 14 App Router, React 18, Mongoose 8, MapTiler JS SDK. No test framework is installed (`package.json` has only `lint`/`build`) — verification uses lint + build + a live dev-server check + a direct Mongo `$expr` sanity query (see Task 9).

## Current context / assumptions

**Data model** (`models/Restate.js:36-47`): each property has
```js
rooms_info: [{ info: String, id: Number, beds: [String] }]
```
where every `beds[i]` is one of the 5 values in `BED_TYPES` (`components/shared/bedTypes.js:4-10`):
`'King size', 'Double bed', 'Single bed', 'Bunk bed', 'Children bed'`, capped at 15/room.

**Existing filter pipeline (the pattern we copy):**
| Layer | File | Role |
|---|---|---|
| Tags + param builder + client gate | `components/amenityFilter/amenityTags.js` | `AMENITY_TAGS`, `buildAmenityParams(ids)`, `matchesAmenities(prop, ids)` |
| State | `app/context/FilterContext.js` | `selectedAmenities: []`, `toggleAmenity`, `resetAmenities` |
| UI | `components/amenityFilter/AmenityFilter.js` (+ `.module.css`) | pill row in header |
| Header wiring | `app/header.js:11-13` | renders `<PriceFilter/> <AmenityFilter/>` in `.filterRow` |
| API route | `app/api/route.js:29,43,46` | `buildFilterQuery(...)`, projection, `find(filter, projection)` |
| Mongo builder | `utils/filters.js:13-85` | `FILTER_WHITELIST` → flat `eq`/`$in`/range ops |

**Key facts that shape the design:**
- `buildFilterQuery` only supports flat field operators. Beds need a **nested-array count**, so they get their own `$expr` builder (`utils/bedFilters.js`) merged into the route filter — we do NOT force beds through the flat whitelist.
- The client gates already-loaded markers instantly (narrowing) and refetches on widening (`app/(home)/page.js:310-327`). For that to work with beds, `rooms_info.beds` must be **projected** in the API response so the client gate has the data.
- The sidebar (`changePoints`) is derived from `marks`, and `marks` already applies the price + amenity gates — adding a bed gate to `marks` keeps the sidebar in sync for free.

### ⚠️ Interpretation decision (please confirm)
The tag label is "Two separate beds". I am implementing your **explicit definition**: *"two variants of the same type of bed in any room"* → a property matches if **some single room contains ≥ 2 beds of one identical type** (e.g. `beds: ['Single bed','Single bed']` ✓; `['King size','Single bed']` ✗; `['Double bed']` ✗).

The universal filter generalizes this to **(count N, type T)** where `T` is a specific bed type **or** `'any'`:
- `beds:2:any` = the requested "Two separate beds" (some room has 2 of one type).
- `beds:3:King size` = some room has ≥ 3 King-size beds.

If you actually meant "any two beds, regardless of type" (king+single counts), that's a one-line change to the predicate — see Open Questions. I proceed with your stated definition.

### Task 1: Server `$expr` builder (`utils/bedFilters.js`)

**Objective:** Produce a correct, index-safe Mongo predicate for "some room has ≥ N beds of type T" (T = specific or `'any'`), plus parse the URL param.

**Files:** Create `utils/bedFilters.js`

**Step 1: Write the file**
```js
// Server-side bed filter: builds a MongoDB $expr predicate that matches
// properties having >= N beds of a given type (or 'any') in ANY single room.
// Beds live in rooms_info[].beds (nested array), so flat whitelist operators
// in utils/filters.js can't express this — hence the dedicated $expr builder.
import { BED_TYPES } from '../components/shared/bedTypes.js'

// Count of `type` inside one room's beds array ($$room is the map var).
function countOfTypeExpr(type) {
  return {
    $size: {
      $filter: {
        input: { $ifNull: ['$$room.beds', []] },
        as: 'b',
        cond: { $eq: ['$$b', type] },
      },
    },
  }
}

// Max, over all rooms, of (per-room expression). Appends 0 so an empty/absent
// rooms_info yields 0 instead of erroring.
function maxOverRoomsExpr(perRoomExpr) {
  return {
    $max: [
      {
        $concatArrays: [
          {
            $map: {
              input: { $ifNull: ['$rooms_info', []] },
              as: 'room',
              in: perRoomExpr,
            },
          },
          [0],
        ],
      },
    ],
  }
}

/**
 * Build the $expr object for one bed spec.
 * @param {{count:number, type:string}} spec  type = a BED_TYPES value or 'any'
 */
export function buildBedExpr({ count, type }) {
  const n = Number(count)
  if (!Number.isFinite(n) || n < 1) return null

  let perRoom
  if (type === 'any') {
    // largest single-type count in the room (i.e. does any type repeat?)
    perRoom = { $max: [BED_TYPES.map((t) => countOfTypeExpr(t))] }
  } else {
    perRoom = countOfTypeExpr(type)
  }
  return { $expr: { $gte: [maxOverRoomsExpr(perRoom), n] } }
}

/**
 * Parse a decoded `beds` param value like "2:any,3:King size"
 * into [{count, type}, ...]. Invalid tokens are dropped.
 */
export function parseBedParam(value) {
  if (!value) return []
  return String(value)
    .split(',')
    .map((tok) => tok.trim())
    .filter(Boolean)
    .map((tok) => {
      const [rawCount, rawType] = tok.split(':')
      const count = Number(rawCount)
      const type = (rawType || '').trim()
      if (!Number.isFinite(count) || count < 1) return null
      if (type !== 'any' && !BED_TYPES.includes(type)) return null
      return { count, type }
    })
    .filter(Boolean)
}

/**
 * Build the Mongo filter fragment for the `beds` query param.
 * Multiple selected tags are AND-ed. Returns {} when nothing valid is set.
 * @param {Record<string,string>} params  plain object of URL query params
 */
export function buildBedFilter(params) {
  const specs = parseBedParam(params.beds)
  if (specs.length === 0) return {}
  const conds = specs.map((s) => buildBedExpr(s)).filter(Boolean)
  if (conds.length === 0) return {}
  // $expr takes a single expression; AND the per-tag conditions together.
  return { $expr: conds.length === 1 ? conds[0] : { $and: conds } }
}
```

**Files:** Create `components/bedFilter/bedTags.js`

**Step 1: Write the file**
```js
// Single source of truth for the bed-filter tags (header).
// A tag = { id, label, count, type } where type is a BED_TYPES value or 'any'.
//   'any'  -> some room has >= count beds of ONE identical type.
//   <type> -> some room has >= count beds of that exact type.
// The id encodes the spec so buildBedParams/matchesBeds can round-trip it.
import { BED_TYPES } from '../shared/bedTypes.js'

// Header shows the requested tag first. Add more universal tags here, e.g.:
//   { id: 'beds:2:Single bed',  label: 'Two single beds',    count: 2, type: 'Single bed' },
//   { id: 'beds:3:King size',   label: 'Three king beds',    count: 3, type: 'King size' },
export const BED_FILTER_TAGS = [
  { id: 'beds:2:any', label: 'Two separate beds', count: 2, type: 'any' },
]

function specFromId(id) {
  const tag = BED_FILTER_TAGS.find((t) => t.id === id)
  return tag || null
}

/**
 * Build URL search-params from selected bed tag ids.
 * e.g. ['beds:2:any','beds:3:King size'] -> { beds: '2:any,3:King size' }
 */
export function buildBedParams(selectedIds) {
  const tokens = (selectedIds || [])
    .map(specFromId)
    .filter(Boolean)
    .map((t) => `${t.count}:${t.type}`)
  return tokens.length ? { beds: tokens.join(',') } : {}
}

// Count of `type` in one room's beds array.
function countTypeInRoom(beds, type) {
  return (beds || []).filter((b) => b === type).length
}

// Does one room satisfy the spec?
function roomMatchesSpec(beds, spec) {
  const list = beds || []
  if (spec.type === 'any') {
    const counts = {}
    for (const b of list) counts[b] = (counts[b] || 0) + 1
    return Object.values(counts).some((c) => c >= spec.count)
  }
  return countTypeInRoom(list, spec.type) >= spec.count
}

/**
 * Client-side gate for already-loaded properties (same pattern as
 * matchesAmenities in amenityTags.js). True when the property satisfies
 * EVERY selected bed tag.
 */
export function matchesBeds(prop, selectedIds) {
  if (!selectedIds || selectedIds.length === 0) return true
  const rooms = prop.rooms_info || []
  return selectedIds.every((id) => {
    const spec = specFromId(id)
    if (!spec) return true
    return rooms.some((room) => roomMatchesSpec(room.beds, spec))
  })
}
```

              key={tag.id}
              role="option"

              className={selected ? styles.tagSelected : styles.tag}

              {tag.label}
            </button>
          )
        })}
        {count > 0 && (
          <button className={styles.reset} onClick={() => resetBeds()}>
            Reset ({count})
          </button>
        )}
      </div>

  )
}

## Risks, tradeoffs, and open questions

1. **`$expr` is not index-accelerated.** The geo part still uses the 2dsphere index; the bed predicate evaluates per document. Fine at Weligama's data scale. If the collection grows large, denormalize a `bedCounts: { 'King size': n, ... }` (or a per-room max-dup field) on write and match it with a flat operator instead.
2. **Projection payload.** Adding `'rooms_info.beds': 1` slightly enlarges each API response (needed for instant client gating). Bounded by ≤15 beds/room; acceptable. If you'd rather keep the payload minimal, drop this projection and rely on server-side filtering + refetch only — but then narrowing won't be instant on already-loaded markers (inconsistent with the amenity behavior).
3. **Interpretation.** I implemented "≥2 beds of one identical type in a single room" per your wording. If you meant "any two beds regardless of type," change `roomMatchesSpec`/the `'any'` branch to `list.length >= spec.count` (client) and the `'any'` `$expr` to a per-room `$size` of `beds` (server). One-line change each — flag it and I'll adjust.
4. **Multiple bed tags = AND.** Selecting "Two separate beds" + "Three king beds" requires both. This mirrors how multiple amenity tags AND together. If you ever want OR, that's a small change to `buildBedFilter` (`$or` instead of `$and`).
5. **No automated tests.** Verification is lint + build + live Mongo/UI checks. If you'd like a real test suite (e.g. vitest for the pure functions in Tasks 1–2), say so and I'll add it as a follow-up task — it's a clean fit since those functions are pure.
6. **CSS offsets** (`top:106px` mobile, `bottom:58px` desktop) are computed from the existing pill geometry; expect a few px of visual tuning after first render.
